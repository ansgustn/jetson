1. 시스템 개요 (System Overview)
====================================================================================================
본 시스템은 제한된 임베디드 자원(NVIDIA Jetson Nano: ARM Cortex-A57 4코어, 4GB LPDDR4 RAM) 환경에서
단일 또는 듀얼 카메라를 통해 사용자의 손동작(Pinch/Grab)과 손목 회전(Rotation)을 실시간으로 추적하고,
이를 Open Sound Control(OSC over UDP) 프로토콜을 통하여 언리얼 엔진(Unreal Engine BP_Knob)으로
30 FPS의 고속/저지연 스트리밍을 제공하는 초경량 비전 인터랙션 프레임워크입니다.

- 주요 성능 지표:
  * 해상도: 640x480 (고정밀) / 320x240 (초고속)
  * 프레임레이트: 25 ~ 30 FPS (Jetson Nano 10W 모드 기준)
  * 통신 지연시간: < 2ms (UDP 로컬 전송)
  * 회전 안정성: 360도 연속 각도 언래핑 및 손가락 가림/왜곡(Foreshortening) 극복

4. 엔드-투-엔드 데이터 파이프라인 흐름도 (End-to-End Dataflow Pipeline)
====================================================================================================

[입력 프레임]
     │
     ▼
[1. 비동기 캡처] ──> ThreadedCamera: 백그라운드 스레드에서 최신 프레임(640x480) 획득
     │               (Buffer Size = 1, Flip = True, MJPG FourCC)
     ▼
[2. 교차 추론 판별] ─> loop_index % 2 검사 (Interleave ON)
     ├── 홀수 프레임: Cam 1 추론 수행 / Cam 2 이전 캐시 유지
     └── 짝수 프레임: Cam 2 추론 수행 / Cam 1 이전 캐시 유지
     │
     ▼
[3. MediaPipe 추론] ─> Tasks API 또는 Solutions API (model_complexity=0)
     │                입력: RGB 640x480 -> 출력: 21개 관절 랜드마크
     ▼
[4. 단일 손 추적 필터] (RobustHandTracker)
     ├─ Handedness 검사: 최초 목표 손(Right/Left)과 불일치 시 기각
     ├─ Jump Distance 검사: 이전 중심점 대비 이동거리 > 120px 시 이상치 기각
     ├─ Coasting 유지: 일시적 미감지 시 이전 속도 벡터로 관성 항법
     └─ 1€ Filter: 21개 랜드마크 좌표 개별 저역 통과 필터링
     │
     ▼
[5. 기하학적 특징 추출]
     ├─ [각도 계산]: calc_robust_hand_angle
     │               - 종축(손목 0 -> 중지뿌리 9) 벡터 u
     │               - 횡축(검지뿌리 5 -> 새끼뿌리 17) 벡터 v (90도 직교 회전 정렬)
     │               - SNR 가중치 w_u = |u|^2, w_v = |v|^2 기반 가중 합성 -> 360도 왜곡 방지
     ├─ [각도 언래핑]: unwrap_angle (-180도 ~ +180도 경계 불연속 제거)
     └─ [핀치 계산]: pinch_ratio_landmarks (엄지-검지 거리 / 손목-중지 길이 정규화)
     │
     ▼
[6. 지능형 센서 융합] (DualCamKnobFuser)
     ├─ 핀치 합의: p_eval = min(p1, p2) (더 가깝게 쥔 시야각 채택)
     ├─ 상태 전이: 슈미트 트리거 + 양방향 2프레임 연속 충족 시 GRAB / RELEASE 전환
     ├─ 각도 델타 융합:
     │    * 동시 회전 시: 회전 평면 정면 시야 카메라에 75% 가중치 부여
     │    * 그랩 진입 순간(Anchor): 초기 핀치 시 발생하는 역방향 비틀림 노이즈(Delta) 폐기
     │    * 그랩 유지 시: 서브픽셀 노이즈 데드밴드(|Delta| < 0.12도 무시) 적용 후 회전 누적
     │    * 릴리즈 상태 시: 회전 누적 중단 (노브 각도 Lock)
     │
     ▼
[7. 초경량 전송] (SimpleUDPClient)
     │  - 패킷 주소: "/mediapipe/knob/angle"
     │  - 인자: [float fused_angle, float send_pinch] (잡음: 0.20, 놓음: 1.50)
     ▼
[8. 언리얼 엔진 반영] -> BP_Knob 컴포넌트 실시간 조작 및 인터랙션 완성

5. 듀얼 카메라 지능형 센서 융합 아키텍처 (Dual-Cam Consensus Fusion)
====================================================================================================

기존 듀얼 카메라 시스템의 가장 큰 문제점은 두 카메라가 각자 독립적으로 메시지를 보낼 때,
시야각 차이로 인해 언리얼 엔진에서 "잡음(Grab) - 놓음(Release)"이 무한히 번갈아 호출되는
채터링(핑퐁 현상)이 발생하는 것이었습니다. 본 시스템은 다음과 같은 합의(Consensus) 구조로 해결합니다:

                  +-------------------+       +-------------------+
                  |   Camera 1 상태   |       |   Camera 2 상태   |
                  | {angle, pinch, q} |       | {angle, pinch, q} |
                  +---------+---------+       +---------+---------+
                            │                           │
                            +-------------+-------------+
                                          │
                                          v
                         +---------------------------------+
                         |      DualCamKnobFuser           |
                         |   (지능형 단일 합의 엔진)       |
                         +----------------+----------------+
                                          │
            ┌─────────────────────────────┴─────────────────────────────┐
            │                                                           │
            ▼                                                           ▼
 [ 핀치 융합 & 상태 머신 ]                                   [ 각도 델타(Delta) 융합 ]
 1) 비대칭 채택: p_eval = min(p1, p2)                        1) Delta1, Delta2 연속 언래핑
 2) 슈미트 트리거(히스테리시스):                             2) 방향 일치 시: 큰 델타(정면 시야) 75% 가중
    - RELEASE -> GRAB : p_eval <= 0.70 (2프레임 연속)        3) 방향 상충 시: 회전이 뚜렷한 카메라 우선
    - GRAB -> RELEASE : p_eval >  0.70 (2프레임 연속)        4) 그랩 시작 순간 앵커링: 델타 강제 0 처리
 3) 언리얼 락(Lock) 값 치환:                                 5) 그랩 상태에서만 노브 각도 누적 (Lock on Rel)
    - GRABBED 중: pinch = 0.20 고정                          6) 서브픽셀 데드밴드: |Delta| < 0.12도 무시
    - RELEASE 중: pinch = 1.50 고정
            │                                                           │
            └─────────────────────────────┬─────────────────────────────┘
                                          │
                                          v
                         +---------------------------------+
                         |      단일 합의(Consensus)       |
                         |       OSC 메시지 생성           |
                         |  [ send_angle, send_pinch ]     |
                         +----------------+----------------+
                                          │
                                          v
                               [ Unreal Engine BP_Knob ]

6. 핵심 기술 혁신 및 알고리즘 세부 메커니즘 (Key Technical Innovations)
====================================================================================================

(1) 직교 너클 바 SNR 가중 합성 각도 산출 (calc_robust_hand_angle)
    - 문제: 사용자가 카메라를 향해 정면으로 손가락을 뻗으면(Foreshortening), 손목-중지 벡터의 2D 길이가
            극단적으로 축소되어 각도가 0도/180도로 튀는 짐벌락(Gimbal Lock) 및 특이점 왜곡 발생.
    - 해결: 손목(0)-중지(9) 종축 벡터와 검지뿌리(5)-새끼뿌리(17) 횡축 너클 바를 90도 회전 정렬 후,
            각 벡터 2D 투영 길이의 제곱(|length|^2, 즉 신호 대 잡음비 SNR)에 비례하여 가중 합성.
            정면 단축 자세에서도 횡축 너클이 80% 이상 가중치를 주도하여 360도 완벽한 회전 연속성 보장.

(2) 그랩 진입 시점 영점 앵커링 (Anchor on Grab Onset)
    - 문제: 사용자가 핀치(집게손)를 쥐는 순간 손가락 근육 수축으로 인해 손목이 반시계 방향으로
            -5도 ~ -15도 가량 자연스럽게 비틀리는 생체역학적 노이즈가 발생하여 노브가 반대로 돌아감.
    - 해결: `grab_just_started` 플래그를 감지한 첫 프레임에는 누적 델타를 강제로 0으로 리셋하고,
            해당 시점의 각도를 새로운 기준 각도로 앵커링하여 쥐는 순간의 반동을 100% 제거.

(3) 비대칭 핀치 융합 (Asymmetric Pinch Fusion)
    - 문제: 한 카메라는 손가락이 맞닿은 것이 잘 보이지만, 다른 카메라는 손바닥에 가려져 핀치가 벌어져 보임.
    - 해결: 두 카메라 중 핀치 비율이 더 작은(더 강하게 쥔 쪽) 카메라의 값을 기준으로 선택하여,
            어느 한 각도에서라도 그랩이 포착되면 조작이 끊기지 않도록 보장.

(4) 1-프레임 교차 추론 (Interleaved Dual-Cam Inference)
    - 문제: Jetson Nano에서 640x480 해상도로 카메라 2대를 매 프레임 동시 추론하면 FPS가 12~14로 급감.
    - 해결: 스레드 카메라 캡처는 30 FPS를 유지하되, 홀수 프레임은 Cam1, 짝수 프레임은 Cam2를 번갈아
            MediaPipe에 전달하고 이전 추론 결과를 캐시하여 결합함으로써 25~30 FPS의 고속 프레임 확보.

(5) 순수 파이썬 초경량 OSC 클라이언트 (SimpleUDPClient)
    - 외부 의존성(python-osc, liblo 등) 없이 표준 라이브러리 `socket`과 `struct`만으로
      Big-Endian 바이너리 OSC 스트림을 직렬화하여 Jetson Nano의 구버전/신버전 환경에 구애받지 않고 동작.


====================================================================================================
7. 파일별 역할 및 모듈 매핑 (Codebase Module Reference)
====================================================================================================

1) `jetson_dual_cam_tracker.py`
   - 시스템의 메인 실행 진입점 (듀얼 카메라 운영 모드).
   - 비동기 스레드 카메라 2대 구동 (`ThreadedCamera`).
   - 교차 추론 스케줄링 (`--interleave`) 및 고정밀 640x480 해상도 지원.
   - 단일 합의 OSC 스트림 송출 및 Headless(초고속 콘솔) / GUI 오버레이 모드 지원.

2) `jetson_knob_tracker.py`
   - 단일 카메라 전용 고성능 트래커 스크립트.
   - Jetson CSI GStreamer 하드웨어 파이프라인 및 USB V4L2 지원.
   - MediaPipe Tasks API 우선 시도 후 Solutions API(`model_complexity=0`) 자동 폴백.

3) `hand_tracker_utils.py`
   - 시스템의 핵심 코어 알고리즘 및 유틸리티 집합.
   - `OneEuroFilter`: 적응형 주파수 컷오프를 가진 1€ 저역 통과 필터.
   - `calc_robust_hand_angle`: 종축-횡축 너클 지능형 합성 360도 각도 계산기.
   - `RobustHandTracker`: 손잡이 잠금, 모션 예측, 가림 관성(Coasting) 트래커.
   - `DualCamKnobFuser`: 채터링 방지 슈미트 트리거 및 센서 융합 상태 엔진.
   - `SimpleUDPClient`: 표준 소켓 기반 경량 OSC 패킷 빌더.

4) `setup_jetson.sh`
   - Jetson Nano 보드 전용 원클릭 자동 세팅 스크립트.
   - 10W MAXN 모드 잠금(`nvpmodel -m 0`, `jetson_clocks`).
   - 4GB Swap 생성, V4L2 video 유저 권한 부여, ARM64 전용 MediaPipe 휠 자동 설치.

5) `requirements_jetson.txt`
   - Jetson Nano 구동을 위한 최소 의존성 정의 (`numpy>=1.19.4,<1.20.0`, `dataclasses`).

6) `evaluate_rotation_models.py`
   - MediaPipe, RTMLib, FreiHAND, Azure Kinect 등 다중 비전 모델의 정확도, 지연시간,
     하드웨어 자원 점유율 벤치마크 평가 스크립트.
